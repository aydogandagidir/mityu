diarize-helper third-party notice - Mityu Windows x64 distribution

Mityu uses `diarize-helper` as a separate executable for on-device speaker
diarization. It is not a library inside the app: it runs as its own process,
once per meeting, over a finished recording (ADR-0034, ADR-0035).

The hash below is of the pinned SOURCE archive, not of diarize-helper.exe
itself. Mityu compiles the helper per release, so its binary hash differs
between builds; quoting one here would be stale, and wrong, the moment it
shipped. The archive hash is the provenance fact that does not move, and it is
verified before every build (tools/diarization/fetch-sherpa-archive.py).

  Built from: sherpa-onnx 1.13.4 prebuilt static archive
    sherpa-onnx-v1.13.4-win-x64-static-MT-Release-no-tts-lib.tar.bz2
    SHA-256:
      79dc88ac71e7a33fd0bb7ac01ee0bc1148dbd6407f44aeca7fa7c0eb9930be33
  Upstream release:
    https://github.com/k2-fsa/sherpa-onnx/releases/tag/v1.13.4

WHY THE "no-tts" BUILD

Upstream also publishes a default archive of the same version built with
text-to-speech enabled. That one statically links eSpeak NG, which is
GPL-3.0. Mityu deliberately builds against the `-no-tts` archive instead, and
verifies on every build that the resulting binary contains no espeak code
(`tools/diarization/check-no-gpl-espeak.py`, run in CI and again in the release
workflow before the binary is bundled).

Mityu therefore distributes NO GPL-licensed code in this executable. Every
component below is under a permissive licence, each verified from its own
upstream repository rather than assumed:
